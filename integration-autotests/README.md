# integration-autotests

Чёрные REST-автотесты для `workflow-engine` (модуль `lab1`). Тесты не используют ни одного
внутреннего класса продакшена: приложение запускается как отдельный процесс ОС и общается с тестами
только по HTTP, а ожидаемый результат проверяется либо по HTTP-ответу, либо чтением `store.json`
сервера с диска как обычного JSON.

Большинство сценариев (`ErrorHandlingBlackBoxTest`, `WorkflowApiBlackBoxTest`,
`StaticResourcesBlackBoxTest`) делят один процесс сервера на весь прогон (см.
`utils/SharedServer`) — каждый такой тест создаёт себе изолированный объект через
`POST /api/objects`, а не мутирует общие seed-объекты. Отдельный процесс на каждый сценарий
по-прежнему поднимают только тесты, для которых это и есть предмет проверки: `PersistenceBlackBoxTest`
(запуск, перезапуск, занятый порт, битый `store.json`) и сценарии с собственной фикстурой
(`broken-template-store.json`, `ambiguous-template-store.json`, `copied-template-store.json`,
`root-template-store.json`) — им нужен свой `store.json` с нестандартной конфигурацией шаблонов.

## Требования

- JDK 21+ и Maven — доступны в `PATH` (тесты сами запускают `mvn -Pweb exec:java` для модуля `lab1`).
- Каталог `lab1` лежит рядом с этим модулем (`../lab1`). Другой путь — через `-Dlab1.dir=<путь>`
  или переменную окружения `LAB1_DIR`.
- Интернет на первый запуск — Allure-плагин один раз скачивает собственный рантайм отчёта (~240 МБ).

## Запуск

```shell
cd integration-autotests
mvn test
```

Большая часть тестов делит один процесс сервера на весь прогон; отдельный процесс поднимается
только там, где это и есть предмет проверки (запуск/перезапуск, собственная фикстура).

## Allure-отчёт

При успешном `mvn test` отчёт не только собирается, но и сразу открывается в браузере по
умолчанию — без блокировки терминала (шаг `open` в `pom.xml` возвращается сразу после запуска
приложения, `mvn test` после этого обычным образом завершается):

```
target/site/allure-maven-plugin/index.html
```

Отчёт генерируется как единый самодостаточный `index.html` (`singleFile=true`) — все данные
встроены прямо в файл, поэтому открытие работает напрямую (`file://`), без локального сервера.

Автооткрытие сделано через macOS-команду `open` (плагин `exec-maven-plugin`, execution
`open-allure-report`). На другой ОС эту цель нужно отключить или заменить аргумент `executable`
на свой аналог (например, `xdg-open` в Linux).

Если часть тестов упала, Maven останавливается раньше генерации отчёта — результаты
(`target/allure-results`) к этому моменту уже на диске, поэтому отчёт можно собрать и открыть
отдельно, без повторного прогона тестов:

```shell
mvn allure:report   # тот же самодостаточный index.html в target/site/allure-maven-plugin
open target/site/allure-maven-plugin/index.html
```
