# Тест-кейсы

Каталог сценариев, которые реально проверяют автотесты в этом модуле, — без ссылок на код и
Java-термины, только то, что происходит с точки зрения клиента REST API `workflow-engine`
(`лаб. 1`). Нумерация сквозная в рамках раздела и привязана к методам в соответствующем
Java-классе (указан в скобках в заголовке раздела) — так же проще искать код по тест-кейсу и
обратно.

Что означает «метод чёрного ящика»: тесты обращаются к запущенному серверу только по HTTP, как
обычный клиент REST API, и ничего не знают про его внутреннее устройство. Ожидаемый результат
проверяется либо по ответу сервера, либо по содержимому файла `store.json` на диске — так же, как
мог бы проверить сторонний инструмент, не имеющий доступа к коду сервера.

Приоритет взят из разметки Allure (`@Severity`): **Критический** — ключевой бизнес-сценарий,
падение ломает защиту прав/денег/данных; **Обычный** — важный, но не самый рискованный путь;
**Незначительный** — вспомогательное/оформительское поведение.
