## Как читать

1. Начните с **компонентов**: движок связывает каталог, шаблон, автомат и хранилище.
2. Посмотрите **иерархию**: офисный заказ наследует параметры и сужает quantity до 1..500.
3. Пройдите **состояния** от начальной точки до «Выполнено»; жёлтые блоки — отложения.
4. Изучите **последовательность**: очередь → проверки → handler → запись → новое состояние.
5. **Хранилище** и **классы** связывают эти действия с данными и Java API.

В диаграмме состояний сохранены все 10 состояний и ровно 19 бизнес-переходов.
Начальная и конечная точки [*] не считаются дополнительными состояниями.
Подписи действий переведены на русский; точные id и условия есть в подробной схеме.
«Отложить решение» соответствует postpone_review, а «Отложить выполнение» —
postpone_execution: оба ведут в отложенное выполнение, но из разных состояний.

Связи компонентов показаны по назначению взаимодействия: интерфейс Repository,
фабрика и callback-адаптер не вынесены в отдельные узлы. Проверка условий у автомата
по-прежнему подключается через callback, а не через знание конкретного заказа.
Последовательность показывает успешный путь; после отказа записи и состояния
не меняются. Изменение состояния выполняется только после успешного commit.

В модели хранения блоки «Каталог», «Объекты» и т.п. — пояснения к настоящим
массивам JSON, а не дополнительные поля документа. Очередь на диск не сохраняется.
В предметной иерархии стрелки обозначают наследование данных, не Java extends.

## Повторная генерация

Из корня проекта, указав путь к своему PlantUML JAR:

```shell
java -Djava.awt.headless=true -jar path/to/plantuml.jar -charset UTF-8 -checkonly "docs/diagrams/simple/*.puml"
java -Djava.awt.headless=true -jar path/to/plantuml.jar -charset UTF-8 -tsvg -o rendered "docs/diagrams/simple/*.puml"
```

В PowerShell заключите JVM-аргумент в кавычки: `'-Djava.awt.headless=true'`.
Исходники используют тот же PlantUML и встроенный Smetana, что подробные версии.
