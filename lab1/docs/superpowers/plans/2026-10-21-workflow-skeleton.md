# План каркаса workflow-engine

**Цель:** подготовить компилируемые универсальные модели и контракты для работы
№ 3-1-1, вариант Б.3, без реализации исполнения процессов.

**Архитектура:** один Maven-модуль, пакеты по компонентам; общие records в `model`.
**Стек:** Java 21, Maven, Jackson Databind / JavaTime, JUnit 5.
**Спецификация:** [architecture.md](../../architecture.md), требования пользователя.

## Ограничения

- Состояния, действия, типы параметров и операторы представлены строками.
- Никаких классов для отдельных видов заказов и данных процесса Б.3.
- Единственный рабочий JSON-документ; seed хранится отдельно в resources.
- Только модели, интерфейсы и документация; исполняемая логика — позднее.
- Тесты будущих файловых реализаций работают во временных каталогах.
- Работа в предоставленном `lab1`, без коммитов и новых веток.

## Задачи

1. Изучить репозиторий и доступные JDK/Maven.
2. Создать `pom.xml`, подключить зависимости и задать `release=21`.
3. Создать records в `src/main/java/ru/moipis/workflow/model/` для метаданных,
   процесса, ДНФ, объектов, событий, истории и корневого `StoreData`.
4. Создать интерфейсы в `catalog`, `statemachine`, `engine`, `condition`,
   `repository`; очередь, текущее состояние и guard отразить в контракте автомата.
5. Создать пустой seed заданного формата, `README.md` и `docs/architecture.md`.
6. Выполнить `mvn clean compile` на JDK 21, проверить изменения и показать результат.

## Проверка границ

- `final` в JSON связывается с допустимым Java-именем `terminal`.
- Числовые границы — `BigDecimal`, значения — `JsonNode`.
- Условие перехода может отсутствовать, литералы допускают отрицание.
- Автомат не получает зависимости на каталог, файловое хранение или виды заказов.
- Отсутствие seed-данных и runtime явно обозначено в документации.

Тесты, дублирующие объявления records и интерфейсов, на этом этапе не добавляются.
Критерий проверки: успешная компиляция всех исходников через Maven с `release=21`.
