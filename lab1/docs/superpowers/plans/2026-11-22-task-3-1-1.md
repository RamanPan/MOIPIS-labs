# План приведения задания 3-1-1 к актуальной редакции

> Этапы отмечаются при реализации. План рассчитан на последовательное выполнение с проверкой каждого этапа.

**Цель.** Показать процесс Б.3 над готовым заказом и выполнить требования актуального задания через браузер и консоль.

**Архитектура.** Два входа передают команды одному и тому же исполнителю на базе `CoordinationSession`. Каждый запуск приложения создаёт свой сеанс в памяти и сохраняет только его журнал JSONL. Веб-режим 3-1-1 использует существующие интерфейс, граф и выбор пользователя. Прежние профили `web` и `coordination` остаются доступными для своих сценариев.

**Стек.** Java 21, Maven 3.9+, Jackson, Javalin, JUnit 5, существующие HTML/CSS/JavaScript и Cytoscape.

**Основание.** `lab1/task/task_3-1-1.pdf`, § 2.1–2.4, § 3 и рис. 3, § 4 и требования к отчёту. Сравнение редакций находится в `lab1/task/report-3-1-1-comparison.md`. Оба документа находятся в локальной папке `task`. Исходный код взят из `main` на `76d0983`.

## Требования к реализации

- Описать роли, пользователей, классы, исходные объекты, состояния, действия и переходы в JSON. Граф Б.3 сохранить целиком, включая 10 состояний, 19 переходов и возвраты. Ядро получает конкретные имена и правила из конфигурации.
- Выбрать наследование параметров. Подкласс получает параметры предков и целиком переопределяет одноимённый параметр с сохранением его типа. «Согласование состава» остаётся названием этапа Б.3. Для выбранного механизма достаточно скалярных параметров.
- Привязать шаблон непосредственно к классу демонстрационного заказа. Загруженный заказ существует до `start`. Процесс содержит состояние отдельного экземпляра, а объект содержит параметры. Для одного объекта возможен один запуск за сеанс, в том числе при наличии двух одновременно пришедших запросов.
- Обработать `start` и `action`. Проверять существование объекта и пользователя, роль запуска или текущего состояния, доступность действия и условие. Если подходят несколько переходов, вернуть ошибку. Если несколько групп ДНФ истинны в одном условии, это один переход.
- Покрыть «И», «ИЛИ», `not`, диапазон фактического класса, наследование и скалярный `default`. Пропущенное поле получает эффективный `default`, явный `null` остаётся незаданным. Предикат по незаданному значению или отсутствующему у класса параметру даёт `false`, к которому затем применяется `not`. Пустая строка считается заданной.
- Отдельная запись JSONL для каждой внешней команды, включая отказ и ошибку формата. В записи есть исходная команда, пользователь, объект, состояния до и после, результат и причина. Чтение данных не создаёт записей. При новом запуске исходные данные загрузятся снова, процессы будут отсутствовать, старые логи останутся доступны как файлы.
- Для защиты нужны сценарий из браузера, автоматические проверки, инструкция, полный электронный отчёт и распечатанный титульный лист ЛЭТИ. Веб-режим должен давать преподавателю возможность увидеть результат на экране и скачать исходный JSONL.

## Пограничные случаи для проверки

| Случай | Ожидаемое поведение | Этап |
| --- | --- | --- |
| Пропущенное поле, явный `null` и поле, отсутствующее в классе | Подстановка только для пропущенного поля, остальные значения остаются незаданными. | 1 |
| Повторный или одновременный запуск | Один успешный запуск, отказ каждой следующей команде с текущим состоянием в обоих полях. | 2 |
| Две истинные группы одного условия и два подходящих перехода | Успех для одного перехода, ошибка для двух. | 2 |
| Команда с неизвестным типом, некорректным JSON или неизвестным объектом | Понятный ответ и запись журнала, включая исходный запрос. | 2–3 |
| Обновление страницы, смена роли и перезапуск сервера | Обновление страницы читает действующий сеанс, смена роли меняет доступ, перезапуск создаёт новый сеанс без процессов. | 3–4 |

## Этап 2. Команды, журнал и консоль

**Файлы.** `engine/CoordinationSession.java`, `engine/CoordinationJournal.java`, новый `engine/Task311Commands.java`, новый `demo/Task311DemoApplication.java`, `pom.xml`.

**Контракт.** `Task311Commands.submit(String rawCommand)` возвращает запись журнала. Одна строка или тело запроса содержат `{"type":"start","userId":"…","objectId":"…"}` либо `{"type":"action","userId":"…","objectId":"…","actionId":"…"}`. Запись содержит `id`, `timestamp`, `command`, `userId`, `objectId`, `before`, `after`, `outcome` и `reason`. `command` хранит JSON исходной команды или её исходный текст для неразбираемой строки. `outcome` принимает `SUCCESS`, `REJECTED`, `ERROR`, у успеха `reason=null`. Если участник или объект неизвестен, сохранять переданный ID при наличии, а неопределимое состояние оставлять `null`.

## Этап 3. API сеанса и журнала

**Файлы.** `web/WebServerFactory.java`, новые `web/Task311WebApplication.java`, `web/Task311ApiController.java` и `web/Task311QueryAdapter.java`, DTO в `web/dto`, `pom.xml`. Новый профиль `web-3-1-1` поднимает интерфейс на `127.0.0.1:7071`.

| Запрос | Результат |
| --- | --- |
| `GET /api/meta` | `mode: "task-3-1-1"` в новом профиле, `mode: "legacy"` в прежнем. |
| `GET /api/users`, `GET /api/objects`, `GET /api/objects/{id}` | Пользователи и готовые заказы. До запуска `stateId=null`. Детали включают эффективные значения и определения параметров, `templateId` берётся по точному классу или равен `null`. |
| `GET /api/objects/{id}/process` | Граф шаблона можно прочитать до запуска, при этом `currentStateId=null`. Если у класса шаблона нет, HTTP 200 с JSON `null`. |
| `GET /api/objects/{id}/access?userId=…` | `stateId`, `canStart`, `startBlockedReason`, `availableActions` и `stateActions`. Последнее поле содержит действия текущего состояния с флагом `allowedByRole` для выбранного пользователя. ДНФ проверяется при выполнении команды. |
| `POST /api/commands` | Тело передаётся в `Task311Commands.submit` даже при ошибке JSON, чтобы журналировать каждый запрос. При успехе HTTP 200 и запись команды. При отказе вернуть существующую форму `ApiError(code, message, details)` с `details.entryId`. |
| `GET /api/journal` и `GET /api/journal?objectId=…` | Записи текущего сеанса в порядке выполнения. В полном журнале видны ошибки, для которых объект неизвестен или не был передан. |
| `GET /api/journal/download` | Снимок текущего журнала в JSONL для скачивания. Содержит те же записи, что и полный журнал. |
