# Workflow Manager — движок бизнес-процессов и веб-интерфейс

Дисциплина: **«Модели объектов и процессов информационных систем»**.

Учебная работа **№ 3-1-1 «Приёмы моделирования бизнес-логики»**.

Вариант **Б.3 «Управление заказом на поставку стандартной продукции»**.

Java-приложение исполняет процессы по JSON-шаблонам и предоставляет локальный
веб-интерфейс управления заказами. Каталог классов, роли, параметры, действия,
состояния и условия задаются данными. Веб-слой использует существующий
WorkflowEngine и FileRepository; бизнес-правила остаются в ядре.

В начальной конфигурации — **10 состояний и 19 переходов Б.3**, шесть ролей,
семь учебных пользователей и пять примеров заказов. Иерархия классов:
`order → standard_order → office_order / consumables_order`.

## Быстрый запуск

Требуются **JDK 21** и **Maven 3.9+**. Выполняйте команды из каталога `lab1`.
`JAVA_HOME` должен указывать на JDK 21; проверьте `mvn -version`.

```shell
mvn -Pweb compile exec:java
```

Откройте **http://127.0.0.1:7070/**. Сервер слушает только loopback-интерфейс.

1. Выберите учебного пользователя в верхней панели; рядом отображаются его роли.
2. Откройте существующий заказ или нажмите «Новый заказ».
3. В карточке используйте доступные действия и редактируйте разрешённые параметры.
4. На вкладке «История изменений» просмотрите подтверждённые операции.

По умолчанию используется постоянный файл **`demo/web/store.json`**. При первом
запуске он создаётся из seed; повторный запуск сохраняет заказы и историю.
Изменение seed не обновляет уже существующее хранилище.

### Другой путь к хранилищу

```shell
mvn -Pweb compile exec:java "-Dexec.args=--store demo/my-web/store.json"
```

Либо задайте переменную `WORKFLOW_WEB_STORE`. Аргумент `--store` имеет приоритет.
В PowerShell путь с пробелами удобно передать через переменную окружения:

```powershell
$env:WORKFLOW_WEB_STORE = 'E:\Workflow data\store.json'
mvn -Pweb compile exec:java
```

Используйте один процесс/движок на один JSON-файл. Остановка — Ctrl+C:
HTTP-сервер прекращает работу, движок завершает принятые команды и workers.

### Запуск из IntelliJ IDEA

- Project SDK — JDK 21.
- Main class — `ru.moipis.workflow.web.WebApplication`.
- Working directory — каталог `lab1`.
- При необходимости Program arguments — `--store demo/my-web/store.json`.

После изменения Java-кода перезапустите приложение. Для обновления страницы
после изменения ресурсов можно использовать Ctrl+F5. Если порт 7070 занят,
завершите предыдущий экземпляр сервера перед повторным запуском.

В текущем локальном Windows-окружении также доступен Maven в `.tools`:

```powershell
$env:JAVA_HOME = 'C:\Program Files\JetBrains\JetBrains Rider 2025.3.3\jbr'
& .\.tools\apache-maven-3.9.9\bin\mvn.cmd '-Dmaven.repo.local=.tools/m2' -Pweb compile exec:java
```

Этот вариант требует наличия указанных локальных инструментов. Обычный запуск
через установленный Maven не зависит от каталога `.tools`.

## Возможности веб-интерфейса

| Область | Возможности |
| --- | --- |
| Список заказов | Номер, наименование, класс, состояние; поиск, фильтр и обновление с backend. |
| Создание | Выбор класса с процессом; динамические поля из эффективных определений параметров. |
| Карточка | Данные заказа, действующий шаблон, выбранный пользователь и его роли. |
| Граф | Все состояния и переходы шаблона, подписи действий, активное/начальное/конечное и посещённые состояния; zoom/pan, fit и текстовая схема. |
| Действия | Кнопки из `/access`, блокировка повторного нажатия, ожидание результата движка. |
| Параметры | Редактирование разрешённых полей через PATCH; конечный заказ доступен только для чтения. |
| История | Timeline с датой, пользователем, операцией, состояниями, действием и значениями до/после. |
| UX | Адаптивная сетка, клавиатурная навигация, labels, focus, aria-live, загрузка, пустые состояния и ошибки. |

После операции UI перечитывает объект, процесс, разрешения и историю.
Отказ показывает сообщение backend, сохраняет ввод и не создаёт локального
перехода или фиктивной записи. При сбое чтения истории остаются ранее
подтверждённые записи с предупреждением. Смена пользователя обновляет доступ,
сохраняя вкладку, раскрытые записи и положение графа; изменение состояния
в ответе backend вызывает полную синхронизацию.

### Создание и выбор класса

Форма получает классы из `/api/classes`, а поля — из
`/api/classes/{classId}/parameters`. Поддержаны `string`, `integer`, `decimal`,
незаданные значения, null и пустая строка. Черновики живут до перезагрузки
страницы; заказы сохраняются на сервере. Пользовательские значения выводятся
через `textContent`, точные decimal и большие целые передаются без округления.

Поле `templateId` в каталоге указывает собственный или ближайший унаследованный
процесс. Форма предлагает классы с непустым `templateId`. Исходный базовый
`order` остаётся в полном каталоге с `templateId:null`: шаблон его потомка
`standard_order` вверх не наследуется. Прямой POST для класса без процесса
возвращает **409 / `NO_PROCESS_TEMPLATE`**, не изменяя хранилище. Если классу
назначить процесс, он становится доступен без изменения списка классов в JS.

Тип параметра проверяется при создании и редактировании. Диапазоны `min/max`
показаны как подсказки и проверяются предикатами при переходах. Поэтому
`office_order` можно сохранить с `quantity=700`, но согласование состава
отклоняется до исправления количества и выполнения остальных условий.

### Граф и история

Cytoscape строит граф из `/api/objects/{id}/process`, включая унаследованный
шаблон. Схемы Б.3 в JavaScript нет. Клик по узлу показывает информацию;
перевод заказа выполняется только действием через WorkflowEngine.
Текущее состояние приходит с backend, посещённые — из реальной истории.

Используется локальный WebJar `org.webjars.npm:cytoscape:3.34.1`.
Фактический путь внутри dependency JAR проверен:

```text
META-INF/resources/webjars/cytoscape/3.34.1/dist/cytoscape.min.js
```

Javalin обслуживает его по `/webjars/cytoscape/3.34.1/dist/cytoscape.min.js`.
Если библиотека недоступна, остаётся текстовый перечень состояний и переходов.
Внешние CDN и шрифты не используются.

Timeline загружает только `/history`. CREATE показывает исходный снимок
параметров и первоначальный номер, даже если заказ переименован. Причина
перехода отображается только при её наличии в записи backend. Дата и время
показываются в часовом поясе браузера; в JSON хранится UTC Instant.

### Порядок выполнения команды

`executeAction` и `updateParameter` проходят одну FIFO-очередь объекта.
Worker проверяет актуальное состояние, роль и условия; один истинный переход
исполняется, ни одного — отказ, несколько — неоднозначность. При создании
используется отдельный executor существующего движка.

Порядок фиксации: **проверки → handler → commit объекта и истории → публикация
состояния автомата → завершение future → HTTP-ответ**. `ctx.future()` ожидает
результат асинхронно. Контроллер не реализует бизнес-правила и не создаёт вторую
очередь. Разные объекты имеют отдельные лениво создаваемые автоматы и workers.

Роли для создания берутся из `createRoles`, для действия — из текущего состояния.
`/access` не фильтрует действия по ДНФ: наличие кнопки не гарантирует прохождение
условия при исполнении. `getAccess` и команды используют общую политику ядра.

## REST API

Базовый адрес — `http://127.0.0.1:7070/api`. Тело изменяющих запросов — JSON.
`userId` задаёт учебного инициатора; реальной аутентификации нет, произвольный
CORS не включён.

| Метод | Путь | Назначение |
| --- | --- | --- |
| GET | `/api/users` | Пользователи, роли и их названия. |
| GET | `/api/classes` | Полный каталог: id, title, parentId, nullable templateId. |
| GET | `/api/classes/{classId}/parameters` | Эффективные определения параметров. |
| GET | `/api/objects` | Сохранённые объекты с названиями классов и состояний. |
| POST | `/api/objects` | Создание объекта. |
| GET | `/api/objects/{id}` | Карточка, значения и определения параметров. |
| GET | `/api/objects/{id}/process` | Действующий шаблон, все состояния и переходы. |
| GET | `/api/objects/{id}/access?userId=...` | canEditParameters, editableParameterIds, availableActions. |
| GET | `/api/objects/{id}/history` | Подтверждённая история по времени. |
| PATCH | `/api/objects/{id}/parameters/{parameterId}` | Изменение одного значения. |
| POST | `/api/objects/{id}/actions` | Выполнение действия через очередь. |

Пример тела POST создания:

```json
{"userId":"user_manager","classId":"office_order","parameters":{"order_number":"WEB-001","quantity":700}}
```

Ответ — 201 с `Location` и данными сохранённого объекта. PATCH принимает
`{"userId":"user_manager","value":100}`; `value:null` очищает значение,
пропущенный `value` даёт 400.

Пример действия над исходным заказом в состоянии регистрации:

```http
POST /api/objects/demo-office-valid/actions HTTP/1.1
Host: 127.0.0.1:7070
Content-Type: application/json

{"userId":"user_manager","actionId":"complete"}
```

При успешном завершении ответ 200:

```json
{"previousStateId":"registration","currentStateId":"composition_approval","handlerResult":null}
```

Для последующих действий запрашивайте `/access`: повторный `complete` в новом
состоянии уже недоступен. `/process` использует сохранённый `templateId` объекта,
поэтому новая копия шаблона подкласса не перепривязывает старые заказы.

Ошибки имеют единый формат `{code,message,details}`:

| HTTP | Причина |
| --- | --- |
| 400 | Неверный запрос, тип или параметр. |
| 403 | Недостаточные права. |
| 404 | Неизвестный ресурс или пользователь. |
| 409 | Неподходящее действие/состояние, ложное условие, неоднозначность, конфликт; отсутствие процесса — NO_PROCESS_TEMPLATE. |
| 415 | Неподдерживаемый Content-Type. |
| 500 | Сбой хранения, handler или другая ошибка конфигурации. |
| 503 | Движок закрыт. |

Ответы 5xx не раскрывают stack trace и внутренние сообщения исключений.

## Хранение и перезапуск

StoreData объединяет `schemaVersion`, `classes`, `roles`, `users`, `templates`,
`objects`, `history`. FileRepository записывает новый снимок во временный файл
рядом с рабочим, вызывает `FileChannel.force(true)` и атомарно заменяет файл
через `ATOMIC_MOVE`. Объект и запись CREATE/ACTION/UPDATE_PARAMETER сохраняются
вместе. Если атомарная замена не удалась, операция отклоняется.

После перезапуска состояние восстанавливается из `stateId`, процесс — по
`templateId`, история и параметры — из того же JSON. Повреждённое хранилище
вызывает ошибку, а не сброс к seed. Веб-приложение по умолчанию не затрагивает
`data/store.json`; иной файл используется только при явном выборе пути.

Параметры наследуются от корня к подклассу; совпавший id полностью заменяет
определение с сохранением типа. ДНФ — OR между группами, AND внутри группы,
NOT у литерала. Поддержаны filled, сравнения, in_range и принадлежность классу.
`filled` считает пустую строку заданной: для очистки `block_reason` нужен null.

## Консольная демонстрация

```shell
mvn compile exec:java
```

Без профиля web запускается `ru.moipis.workflow.demo.DemoApplication`.
Каждый раз создаётся новый `demo/run-<суффикс>/store.json`; старые демонстрации
и пользовательский файл не перезаписываются. Русский вывод — UTF-8.

Сценарий показывает создание с quantity=700, отказ согласования и исправление
на 100, возврат correction, запреты роли и редактирования, обе OR-ветви оплаты
и завершение двух заказов. История содержит 13 и 8 записей; четыре ожидаемых
отказа не добавляют событий. Отдельно демонстрируется динамическая регистрация
состояния/handler/перехода работающего автомата. Успешное завершение — `DEMO OK`.

## Ограничения учебной реализации

- Выбор userId не является аутентификацией; приложение предназначено для локальной работы.
- Очереди существуют в памяти, не ограничены по размеру и не восстанавливаются после аварии.
- На активный объект приходится один platform worker; вытеснение неактивных автоматов отсутствует.
- Файловая запись копирует общий JSON-снимок; межпроцессной координации и распределённых транзакций нет.
